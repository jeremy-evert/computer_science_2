# COMSC 1053 — Course Ethos and Weekly Contract

**Stated by Jeremy, 2026-08-06. This is the canonical description of what
the course asks of students and what it gives them.** When another document
in this repo disagrees with this one, this one wins until Jeremy says
otherwise.

## The class in one sentence

A supportive class structure where students extend their programming through
lecture, paired programming, and show-and-tell — with an AI-fluency strand
and a professional-development strand woven through every week — using the
same Coding Odyssey spine as CS1 at greater technical depth.

## The weekly rhythm

This rhythm is shared across Jeremy's courses; shared-strand material is not
recreated in this repository. CS2's actual Fall 2026 meeting schedule is
TBD, so day/time/room details must be confirmed before publishing.

**Every class period (50 min):** 10–15 minutes presented (10 of material, a
few for questions), then 35–40 minutes of active work. The presented segment
uses a slide deck **with a live clock in the corner**. Fifteen minutes is a
hard ceiling.

| Strand | 10–15 min purpose | 35–40 min active work |
|---|---|---|
| **Monday Moment** | AI fluency | Main topic of the week — lecture with live worked examples |
| **Wacky Wednesday** | Professional minds | Paired programming |
| **Fun Friday** | Professional minds | Show-and-tell |

**Week 1 is universal across all courses.** Its actual shared handouts and
activities belong to `semester_kickoff_week`; CS2 references them rather than
recreating them locally.

Each shared strand item ships as a digest document, a time-bounded live demo,
and a humor-forward podcast; the course also has a fourth podcast covering
the technical lecture. The established AI stance applies: **“Trust the tools
less. Love the tools more.”** AI is a tutor, collaborator, and debugging aid,
not a typist. Students disclose assistance and remain able to explain and
verify every submitted line.

## What we ask of students (weekly)

Six recurring student artifacts, each with its reusable template:

1. **Monday Moment practice assignment** — establishes best practices for
   that week's AI-fluency idea.
2. **Wacky Wednesday reflection** — ties the professional-minds lesson to
   the week.
3. **Weekly topic reinforcement** — happens inside the student's Coding
   Odyssey world, not as a separate textbook problem set. The Deitel topic
   supplies the concept; the gate or checkpoint is the artifact. In CS2 that
   means deeper use of exceptions, modules/files, inheritance, recursion,
   plotting, and searching/sorting (`docs/curriculum/course-sequence.md`).
4. **Fun Friday reflection** — ties the professional-minds lesson to the
   week.
5. **Paired-programming report** — evaluates the student's contribution,
   including driver/navigator collaboration.
6. **Friday feedback report** — evaluates the feedback the student gave in
   show-and-tell.

## What we give students

1. Slide presentations in class — shared-strand decks plus technical lecture.
2. Transcriptions of class recordings.
3. A written technical text for the material taught.
4. A chat bot for discussing ideas, consistent with the tutor-not-typist and
   Marker/Coach doctrine.
5. Worked solutions — nothing hidden; students see what good work looks like.
6. Automated Canvas feedback through the Harbor → Guidepost → Marker → Coach
   pipeline, so no student waits in silence.
7. A shared repository where the class shares code and ideas.
8. A supportive class structure: practice, visible progress, explanation,
   revision, and asking for help are core expectations.

## Grading direction

- **No traditional tests.** Points come from weekly artifacts.
- The named categories and weights are in `docs/grading-model.md`.
- The weekly reinforcement assignment is graded on working result and
  process: rhetoric, planning, tool transparency, and knowledge management.
- The final is a reflection paper, based on `assignments/A5-final-reflection.md`.
- **Collaboration is encouraged.** Pairs may share one repository; each
  student documents their contribution, with no more lopsided than an 80/20
  lines-of-code split.
- **Resource budgeting is a graded skill, not an equity filter.** Full credit
  is available with free/local tools; what matters is transparent reasoning.
