# Show Your Work (Week 14, optional, no new deliverable)

By the end of this course you will have made something worth showing. This week connects to the Culmination Design Review: a runnable slice, important tests, design rationale, usable documentation and clean-enough history are the same things a stranger looks for in a repo.

Read the one-page guide first: https://jeremy-evert.github.io/swosu-computing/show-your-work/

What to look for this week:

- **Explain it:** README first screen: what it is, how to run it, how to run the tests.
- **Tell the truth about limits:** name what is untested or unfinished. Naming a gap is a strength.
- **Credit it:** everything you did not make, with its license.
- **Look at the history:** check for secrets, paths and other people's data before anything is public.

The same path as a 50-minute deck: https://jeremy-evert.github.io/swosu-computing/show-your-work/lecture/

Before you publish anything, tick the checklist: https://github.com/jeremy-evert/oeqa_spell_roller_public/blob/main/CHECKLIST.md

Pick one thing you made, find the first checklist box it fails, and fix that one box. That is the whole task.
