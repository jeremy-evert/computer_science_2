## Source-of-truth order

The syllabus must match the course, not the other way around. When sources conflict, use this order:

1. current course `course_metadata.yaml` and explicit owner decisions;
2. current `planning/` / semester spine and `docs/grading-model.md`;
3. canonical shared curriculum policies such as office hours and late work;
4. current university syllabus/template requirements;
5. historical syllabi only as provenance or reusable prose.

Do not reintroduce an old room, class time, textbook requirement, attendance ladder, grading split, or technical sequence merely because it appears in an older Word syllabus.

## Canvas requirement

The current syllabus needs to be loaded onto the Fall 2026 Canvas **Syllabus** surface for this course. Presence in GitHub does **not** prove Canvas publication. After loading, perform a student-facing read-back and preserve evidence that the Canvas syllabus matches the repository source.

Production Canvas credentials are not implied by this note. If the current operating boundary is manual Canvas work, load it manually rather than restoring a token just to satisfy this task.

## Maintenance rule

If course facts change, update the authoritative repo source first, regenerate/review the syllabus artifact, then update Canvas. Keep Git, the rendered syllabus, and the student-facing Canvas surface telling one story.
