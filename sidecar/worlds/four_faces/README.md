# The Four Faces -- Master Guide

Internal canon. Built by Prompt 019
(`../../prompts/019_four_faces_recurring_world_characters.md`), deepening
the four Jeremy personas first named in Prompt 017
(`../README.md` and each world bible's section 5). Not student-facing.

## The core idea

Each of the four personas is **an amplified facet of Jeremy**, not a
costume, not an impression, not a parody. Four modes he already
inhabits, each turned up in one world:

| World | Facet | Persona |
|---|---|---|
| Frontier Settlement | the practical builder | Garrett Boone -- `frontier_garrett_boone.md` |
| Investigation Bureau | the verifier | Chief Nora Arana -- `investigation_chief_arana.md` |
| Starship Log | the commander/explorer | Commander Elias Rourke -- `starship_commander_rourke.md` |
| Small Business | the operator | Frank Delgado -- `small_business_frank_delgado.md` |

This is why the performances are sustainable across a whole semester:
Jeremy isn't building four actors from nothing, he's dialing up four
things he already does naturally, then putting on the corresponding
visual cue.

## Shared performance philosophy

**Start from character, not costume.** The prop tells the audience who
walked in; the character is what makes the next thirty seconds work.
If the writing is right, the prop is almost optional.

**Voice comes from posture, word choice, cadence, and attitude --
never from accent or impersonation.** No dialect performance, no
ethnicity- or nationality-coded voice, nothing that requires "doing a
voice" in the impressionist sense. Garrett is plainspoken and
unhurried. Arana is measured and economical. Rourke is calm and
forward-leaning. Frank is warm and direct. Those are postures and
word-choices, not accents.

**Believe the world is real.** None of the four is in on a joke about
their own setting. That sincerity is the entire engine -- the moment a
persona winks at the camera about being a "frontier guy" or a "space
guy," the bit dies. Play it straight; let the situations carry the
warmth and the humor.

**One prop, one posture change, one line.** Every persona should be
identifiable within the first three seconds from a single visual cue
(see each dossier's "recurring prop/visual identifier") plus how
Jeremy is standing/sitting. The line confirms it; the prop and posture
should already have told the audience who it is.

**Thirty to ninety seconds, one take.** Every sample script in the
four dossiers is written for a desk, a hallway, or a simple background
-- no set, no crew, no multi-take dependency. If a bit needs more than
that to land, it's over-written; cut it.

**Leave room to improvise.** Each dossier's "5-10 voice lines" section
demonstrates the voice; it is not a script to memorize verbatim.
Jeremy should be able to riff inside the boundaries and still be
canonically the same character.

## The academic firewall (repeated deliberately -- do not weaken this)

These personas create flavor, memory, and motivation. **They do not
control grading.** Every dossier's briefing content must have its real
technical requirement stated in plain course language somewhere
outside the performance -- a student who never watches a single video
must be able to succeed fully. See `../README.md`'s firewall section
for the full doctrine; this file does not relitigate it, only reminds
future authors it applies here too, specifically because these are the
highest-charisma, most-tempting-to-lean-on artifacts in the whole
system.

## Guidance for future agents writing dialogue

1. Read the specific persona's full dossier before writing a single
   line -- especially "phrases/behaviors that do not fit."
2. Match the entrance pattern (each dossier's "canonical entrance") for
   any new briefing unless there's a specific dramatic reason to break
   it (a first-time appearance, an urgent variant, etc.).
3. Check the relationship map before writing a scene with more than
   one character -- these people know things about each other.
4. Check `../continuity_ledger.md` before introducing any new fact;
   add one in the same commit if you introduce something new.
5. Never let a persona's briefing be the *only* place a technical
   requirement is stated. See "academic firewall" above.
6. When unsure whether a line fits the character, prefer the option
   that makes the character sound like they believe the world is real,
   not the option that's funniest in isolation.
