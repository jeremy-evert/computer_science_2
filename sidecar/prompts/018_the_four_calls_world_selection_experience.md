# Prompt 018: The Four Calls — World Selection Experience

**Status:** OPEN  
**Course:** COMSC-1053 Computer Science II, Fall 2026  
**Owner:** Cleo  
**Scope:** Student-facing world-selection experience built from the accepted Reasoning Odyssey and Four Living Worlds canon

## Mission

Build **The Four Calls**.

Students should not choose a Reasoning Odyssey world by reading four dry descriptions on a form.

Each world should **contact them**.

Create four short, distinct, in-character briefings that let students sample the voice, stakes, and texture of each world before they choose where they want to spend the semester.

Then give them one simple question:

> **Which call do you answer?**

This should feel memorable, stylish, surprising, and unmistakably connected to a serious university Computer Science II course.

Do not turn it into a lore exam.

Do not dump the Four Living Worlds Bible on students.

Give them four doors, crack each one open, and let them choose the place they want to return to.

## Dependency and source of truth

Use the current repository source of truth.

Prompt 015 defines the professional CS2 slide system.

Prompt 016 defines the shared Reasoning Odyssey academic contract.

Prompt 017 defines the internal canon, voices, continuity, recurring characters, Jeremy personas, visual identities, and taste boundaries for the four living worlds.

Prompt 018 should consume those systems rather than inventing replacements.

If Prompt 017 is still evolving, draft the structure and production plan, then reconcile scripts and details against the accepted world bibles before final production.

## Governing rule

Preserve the firewall:

> Classroom materials teach the curriculum.  
> The Odyssey defines the work.  
> The worlds make students care what happens next.

The Four Calls are an invitation into the world layer.

They are not a prerequisite for understanding CS2.

A student who dislikes performance, narrative, roleplay, or genre flavor must still be able to choose a world and succeed without penalty.

## The experience

Design the world-selection sequence as one coherent experience.

A strong default shape is:

1. a brief shared setup
2. Call One
3. Call Two
4. Call Three
5. Call Four
6. a clean comparison/choice moment
7. **Which call do you answer?**
8. a simple mechanism for recording the student's choice
9. a short closing message explaining what happens next

Do not make the shared setup longer than the calls themselves.

The point is to hear from the worlds.

## Four calls, four unmistakable voices

The four canonical worlds should be distinct enough that students can recognize them from tone and presentation alone.

Use the accepted Prompt 017 canon for names and specifics.

Current working identities are:

- Frontier Settlement
- Investigation Bureau
- Starship Log
- Small Business

Treat those as working labels if Prompt 017 establishes more precise canonical names.

Each call should reveal only enough to answer three questions:

1. **What kind of place is this?**
2. **What kinds of problems will find me here?**
3. **Would I enjoy coming back to this place all semester?**

Do not explain future plot lines, hidden characters, delayed payoffs, or internal continuity machinery.

Protect the surprise.

## Jeremy is part of the medium

Jeremy is willing to perform the calls.

Use that as a design asset.

Write the primary version of each call as a short script that Jeremy can deliver in character with modest practical production.

The call should be playable with things such as:

- a badge
- a jacket
- suspenders
- a clipboard
- a folder
- a prop document
- a desk setup
- a simple background
- a distinctive title card
- a restrained sound cue if appropriate

Do not build a production that requires a film crew, expensive costumes, elaborate sets, or difficult post-production.

The charm should come from commitment, writing, timing, and recognizable character identity.

## Performance target

Each call should be short.

Aim for roughly **45–90 seconds** unless the material clearly earns more time.

Jeremy should be able to perform the script naturally rather than reading a wall of exposition.

Write for spoken delivery.

Use rhythm, pauses, specific stakes, and one or two memorable lines.

Do not write stand-up comedy routines.

Do not make Jeremy the joke.

The character should believe the world is real.

That sincerity is what makes the bit work.

## A distinct dramatic engine for each world

Each call needs its own reason for contacting the student.

Do not make all four versions of:

> "Hello recruit, we need programmers."

The call should emerge naturally from the world.

Examples of structural possibilities, not mandatory plots:

- a settlement has a growing system that can no longer be managed casually
- an investigator has incomplete evidence and systems that do not agree
- a ship or mission has interacting systems under pressure
- an owner/operator has a functioning organization whose information and processes are beginning to buckle under growth

Use Prompt 017 to make these authentic to the actual world canon.

## No false choice about difficulty

The calls must not imply that one world is easier, harder, more advanced, more prestigious, more technical, or more serious than another.

Students are choosing **context, flavor, and the kind of problems they want to live with**, not a grading tier.

All four worlds must remain aligned to the same CS2 academic outcomes and Reasoning Odyssey contract.

## Scripts

Produce a polished primary script for each call.

Each script should include:

- speaker / character
- intended setting
- performance direction
- prop or wardrobe suggestions
- approximate runtime
- spoken script
- optional cut points if Jeremy wants a shorter version
- any on-screen text that appears during the call
- notes about what the student should understand after viewing

Where useful, create one alternate line or alternate ending so Jeremy has room to find the character in performance.

Do not over-script every gesture.

Leave him room to inhabit it.

## Visual package

Using the Prompt 015 system and Prompt 017 world identities, create a restrained visual package for each call.

At minimum define or produce:

- opening title card
- world identifier
- lower-third / speaker identification if useful
- closing card
- one native artifact or graphic if it strengthens the call

Each world should be recognizable immediately, but the four calls should still feel like members of the same CS2/Reasoning Odyssey family.

## Audio and accessibility

Design the calls so they work with sound, but do not make sound the only carrier of meaning.

Provide:

- captions or caption-ready scripts
- readable on-screen identifiers
- transcript text
- guidance for any sound cue that may need an accessible equivalent

Do not require students to understand an accent, character voice, or subtle audio joke to make an informed choice.

## The choice moment

After the four calls, give students a clean decision point.

The choice moment should feel more substantial than a generic dropdown, but it must remain operationally simple.

The central language should be:

> **Which call do you answer?**

Give students a concise reminder of the four choices without replaying the entire pitch.

Provide practical guidance such as:

- choose the world you are most curious to return to
- do not choose based on perceived difficulty
- you are choosing context, not a different grading standard
- overthinking is unnecessary

If the course source already defines whether switching worlds is allowed and until when, follow that source exactly.

If that policy is unresolved, flag it rather than inventing one.

## Student choice capture

Design a simple mechanism for recording the student's world choice in the LMS/course workflow.

Do not perform production LMS writes unless explicitly authorized by a later deployment workflow.

Specify:

- what students submit/select
- the exact four canonical values
- where the choice should eventually be stored
- what instructors/agents need in order to route future world-specific materials correctly
- how to avoid free-text naming chaos

Prefer a boring, reliable backend even if the front-end experience is delightful.

## Protect the internal canon

Do not reveal:

- future story seeds
- delayed payoffs
- hidden continuity plans
- all recurring characters
- future emergencies or mysteries
- internal authoring rules
- Jeremy's full persona notes

Students should feel that the worlds contain more than they have seen without being shown the backstage machinery.

## First contact should plant one tiny hook

Each call may plant **one small unresolved hook** that could be referenced later if useful.

Examples:

- a number that does not quite reconcile
- a system behaving strangely
- an unexplained request
- a person mentioned but not yet seen
- a policy under pressure
- a constraint that sounds harmless now

Keep it subtle.

The hook should make the world feel alive, not turn the selection experience into a mystery puzzle.

Prompt 017's continuity ledger should record any canonical hook that survives into the final calls.

## Deliverables

Produce:

1. a short shared opening for **The Four Calls**
2. four polished in-character call scripts
3. performance notes for Jeremy for all four calls
4. prop / wardrobe / simple set suggestions
5. title cards and visual-package guidance/assets using the established CS2 system
6. caption-ready transcripts
7. one concise student comparison/choice screen
8. the **Which call do you answer?** selection moment
9. a recommended backend representation for storing world choice
10. a short production checklist Jeremy can use when recording
11. any tiny continuity hooks introduced by the calls, recorded back into the world-authoring system
12. a brief mapping showing that all four calls preserve academic equivalence

## Acceptance criteria

Prompt 018 is complete when:

- students can sample all four worlds without receiving a lore dump
- each call has an unmistakably different voice and dramatic reason for existing
- Jeremy has four playable performances he can realistically record
- each call is short enough to hold attention
- students understand that all worlds share the same academic standard
- no world is framed as easier/harder or better/worse
- captions/transcripts make the experience accessible
- the final choice is simple and memorable
- the selected world can be stored reliably in a future LMS workflow
- the internal canon remains hidden
- each call leaves open the possibility that the world will contact the student again
- any canonical hooks are captured in the continuity system
- the whole experience feels like an invitation, not an assignment explanation

## Explicitly out of scope

Do **not** in this prompt:

- build every future world video
- reveal the complete living-world bibles
- create graded lore quizzes
- require students to roleplay
- create different grading rules by world
- rewrite the shared Reasoning Odyssey contract
- turn normal CS2 classroom slides into four separate tracks
- deploy the world-selection mechanism to production Canvas without explicit authorization

The students have heard four voices.

Now let them choose which one they want to hear again.
