This week's question

When does a predicted noun actually deserve to be its own object?

Reopen your Week 3 World Bible. Pick one candidate from your predicted-object list and test whether it earns a cohesive boundary — an object that owns related state and the behavior that belongs with that state. A prediction that does not hold up is a legitimate finding, not a failure.

Optional — try this first: The Tavern Tab

A tavern keeps a running tab for each patron. A TavernTab owns patron_name and balance:

  • add_charge(amount) raises ValueError if amount <= 0; otherwise increases the balance.
  • pay(amount) raises ValueError if amount <= 0. If amount > balance, it zeroes the balance and returns the overpayment as change; otherwise it reduces the balance by amount and returns 0.

The reasoning beat, same shape as this week's real gate: does TavernTab deserve a cohesive boundary, or is it just a named number? And does the settlement's full ledger of every patron's tab belong inside TavernTab itself? (No — name why: a single tab owns one patron's balance and the rules for changing it; the ledger of every tab is a different responsibility — a collection this object doesn't need to know about.)

One test to write: charge 10, pay 3 → balance 7. Pay 20 → balance 0, change 10.

This is a separate, lightweight, optional warm-up — the SupplyCrate worked example above is still the serious spine for this week's gate.
